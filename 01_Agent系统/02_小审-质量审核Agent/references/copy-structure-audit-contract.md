# 文案结构 V16 独立审核合同

审核活动 `copy-structure-handoff-v16` 与 `copy-structure-v16`。`big_frameworks` 保留全部 FNN；结构一至四只保留可映射处理库的核心框架，按原 FNN 相对顺序一致。非处理库支撑段（如行动引导）必须在 `final_copy_only_frameworks` 中标为正文专属，且不得含小结构、`structure_segments`、逐句或句群字段。历史资产只兼容读取，不按本合同改写。

## 机械门禁

- handoff、候选、选题分析、发布计划和选题表绑定必须锁定同一版本与哈希。
- `content_object_pool` 必须具体、合法；每个非空节点有唯一对象 ID，同一路线不得复用，任两路线对象重合率不得超过 40%。
- 路线必须有受控母角度、五维指纹和逐节点 `new_information` / `builds_on` 推进映射。
- 结构三非空节点必须有同类型正式资产、可回溯路径与哈希，且事实等级为 `asset_backed`；未命中必须整格留空并记录检索缺口。
- 三条结构必须共享标题合同最终结论、各有不同母逻辑，并逐 FNN 证明承接与删段断裂；把案例、误区、方案替换成相关知识点仍不影响链条的，直接退回。
- 结构三每条论据必须附带可在声明章节内定位的连续原文摘录。案例需覆盖事件，误区需覆盖原误区和漏洞/后果/纠正，方案需写明并摘录原始编号步骤。
- 无来源原创内容不得伪造具体人物、数字、平台官方规则或其他可核验事实；待核验内容必须写核验说明。
- 案例必须具备对象、行为/冲突和结果；误区必须含错误认知及其不成立原因/边界；方案有 1–5 条动作化步骤。
- 结构四仍受保护，发布回执、发布计划和发布索引必须绑定当前候选。
- 结构一至四、三套方向比较和结构三出处表不得渲染正文专属支撑段；审核必须验证其不被误当作处理库资产。

## 语义门禁

独立审稿人逐项给出证据并为以下七项各打 0–100 分：选题兑现度、内容具体度、节点独立性、逻辑推进、框架功能正确、论点论据匹配、口播可扩写性。总分为七项平均分，必须不低于 80。

### 结构写作方法审核标准

- **框架功能正确**：每格只完成当前 FNN 大框架的职责，并直接服务标题；不得用观点格写方案，或用误区格只重复痛点。
- **内容具体度**：关键判断必须给出可观察场景、动作、选择、对象或判断标准；只说“有价值、很有用、抓手、机制”等词且未落地，直接退回。
- **逻辑推进**：每个 `new_information` 相对前一节点必须新增原因、代价、边界、例子或动作；只换词复述同一判断，直接退回。
- **论点论据匹配**：论据必须解释当前核心论点为何成立；解决方案的每步必须写明动作、对象与有效信号，收束类框架才可给唯一低门槛行动。
- **口播可扩写性**：每格脱离表格仍是完整意思；设问必须带出答案，概念必须用人话解释；不得把结构卡片扩写为正文段落。
- **判断边界**：不得把必要条件写成唯一条件，不得制造伪对立或让前后节点自相矛盾。

小审的每个 `item_review` 必须引用对应候选的核心论点、论据/步骤或推进逻辑，逐项说明以上标准如何满足；“职责明确、表达一致”等泛化结论不构成证据。

任何一项为真即退回：标题承诺错位、三点以上同一观点、抽象案例、伪多版本、无资产伪装结构三、编造可核验事实。

## 人读稿与发布

正式人读稿按 FNN 显示核心大框架与核心内容，不得泄漏对象 ID、资产路径/哈希或来源锚点。`--debug` 仅限运行区，不能发布。只有 `artifactType=copy-structure-v14`、状态 `approved` 且绑定当前候选、handoff、预览和发布计划哈希的回执可发布。
