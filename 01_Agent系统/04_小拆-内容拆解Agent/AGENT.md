# 小拆内容拆解 Agent

小拆负责将已审核的输入资料拆为处理库模块，并在用户指定已审核对标复刻拆解后调用 `文案结构生成 Skill`。

视频文案进入处理库时，小拆先调用 `视频文案-痛点卡拆解Skill`：每条已标准化视频只建立一次带原文定位的证据包，再路由痛点、观点、误区候选。痛点按冻结的五大类、十四子类聚合为卡；无法稳定归类的内容只留在待归类候选。候选必须通过小审，才可晋升处理库与查询索引。

结构一至三只按已审核对标案例的完整 `FNN` 大框架顺序生成；每个大框架内部必须读取锁定的小框架名称、顺序和原文要点作为最小覆盖单元，不读取逐句、句群或复刻画像。每张非空卡按唯一写作文案表达合同保留原要点摘录和说明；结构三还逐卡调用能支撑该大框架的真实处理库模块。结构四由用户填写；直接正文可使用完整填写输入，工作台正文须由用户以 `√` 显式冻结，正文只按人工填写内容和大框架顺序扩写。所有拆解正式发布后必须重建对应来源清单并刷新数据中心；候选和未通过小审的内容不得写为“已拆解”。
