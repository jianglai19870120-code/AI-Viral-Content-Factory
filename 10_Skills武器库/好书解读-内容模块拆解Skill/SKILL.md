# 好书解读-内容模块拆解Skill

## 范式声明（2026-08-06 反转）

**本 Skill 不自动生成任何模块内容。** 拆书正文必须由 WorkBuddy（LLM）读取原书后直接产出真实、有书源差异的模块文件；脚本只承担两件机械事：

1. `validate_real_content` —— 反模板门禁，扫描候选模块是否含旧版写死的通用废话，命中即不合格、不得晋升、不得进入结构三。
2. `tools/promote_book_real.py` —— 晋升打标脚本（独立工具，不在本 Skill 的 scripts 内）：打标前强制调用 `validate_real_content` 门禁，0 命中才把该书的每条索引打 `source_quality: "real"`；任一命中即拒绝打标（退出码 2）。重构后**不再有候选→正式的复制动作**（LLM 直接把模块写到正式库目录），本脚本只负责索引打标。

> 历史教训：早期版本用 `TITLE_TOPIC_FALLBACKS` / `TITLE_FAMILY_FALLBACKS` 等硬编码主题池 + `mistake_blocks` / `step_blocks` 写死三句通用话术自动生成，导致**整库 ~280 本书 × 14 模块几乎全是模板废话**（外层标题真实、内层正文通用）。已于 2026-08-06 删除全部硬编码主题池、模板生成函数、`apply_title_topic_fallback`、以及「未来的工作」硬编码步骤注入块。脚本不再有任何自动模板生成路径。

## 核心定位

这是整本书内容拆解的正式总入口。

默认场景：

- 用户直接说“拆一本书”
- 用户要把一本书沉淀成干货型内容模块

## 固定输入

- 已进入原始知识库、且已经是正式 `md` 的书类资料
- 默认优先读取：
  - `02_资产中心/01_输入库/清单/书籍清单.md`
  - `02_资产中心/01_输入库/01_推荐好书-源文件/...`

## 固定输出

- `02_资产中心/02_处理库/01_观点_内容模块/01_推荐好书`
- `02_资产中心/02_处理库/03_误区_内容模块/01_推荐好书`
- `02_资产中心/02_处理库/04_解决方案_内容模块/01_推荐好书`
- `02_资产中心/02_处理库/01_观点_内容模块/01_推荐好书/00_索引/模块索引.jsonl`
- `01_Agent系统/04_小拆-内容拆解Agent/99_执行记录/执行记录`
- `01_Agent系统/04_小拆-内容拆解Agent/99_执行记录/正式产物来源`

## 固定规则

1. 只处理已经通过原始资料入库审核的书类 `md`。
2. 输出目标固定是干货型内容模块，不是推荐型内容模块。
3. 反转后 LLM 直接把模块文件写进正式库目录（`02_误区模块` / `03_步骤模块`），门禁+小审通过前索引暂不标记 `source_quality:"real"`（「待审」状态，不得被结构三取用）；通过后由 `tools/promote_book_real.py` 打标 real。不再有独立物理候选产物区目录。
4. 小审通过后，候选产物才允许晋升正式模块。
5. 正式模块晋升完成后，运行 `原始资料入库统计Skill/scripts/refresh_after_approved.py --type books --producer xiaochai --reason book-modules-promoted`；清单与数据中心只能在该 approved 后回写中更新。
5. 金句必须写入聚合文件。
6. 误区、步骤默认写成独立模块文件。
7. 正式执行时必须写入正式产物来源记录。
8. 正式执行后必须回写原始资料入库统计状态。
9. 正式执行后必须交给小审执行正式模块放行审核。
10. 不再把金句 / 故事 / 误区步骤当成独立正式 Skill 路由对象。
11. 充分拆解是最高优先级死规则：拆书不是抽样、不是示例生成、不是固定模板生成。
12. 必须尽可能覆盖整本书中可转化为短视频干货资产的内容，禁止固定产出数量。
13. 禁止每本书都产出相同主题结构；如果执行器只能固定产出 4+4、12+12、13+13 等配平结果，直接视为不合格执行器。
14. 误区文件、步骤文件数量必须由书的真实内容密度决定，误区数量和步骤数量不要求一致，也不应该默认一致。
15. 误区只收明确错误认知、错误做法、错误判断；步骤只收书中确实形成执行链的解决方案。
16. 同一主题可以只有误区、只有步骤，或两者都没有；没有对应步骤时禁止硬套步骤。
17. 禁止标题模板：`以为X可以靠想象直接做对`、`怎么把X变成可验证的行动`、`X要先被验证`、`X要靠行动验证`。
18. 每次拆书必须写入充分拆解记录，分别记录误区候选池、步骤候选池、入库数量、丢弃原因和是否达到充分拆解。
19. 候选主题必须是可转化为短视频干货模块的有效主题，禁止把 `北京 / 比如 / 因此 / 问题 / 樊登老师` 这类地点、人名、连词、泛词、高频噪声词当成模块主题。
20. 如果充分拆解记录中的候选池出现无效主题词、重复主题、误区步骤完全同源或明显通用话术，小审必须退回，不能因为数量变多就放行。
21. `05_模块索引` 只作为机器检索清单和审核依据，不作为用户主要查看入口。
22. `06_标签字典` 当前退役，不再作为本 Skill 的执行和审核必需项。
23. 模块正文必须像短视频可调用内容资产，不得写成书籍解释、作者观点说明或原文依据说明。
24. 正文区禁止出现 `这本书 / 本书 / 作者 / 书中 / 原文 / 依据 / 提到 / 认为 / 强调` 等来源叙述词。
25. 来源只允许保留在文件底部元信息、正式产物来源记录和模块索引中。
26. 金句必须做清洗，过滤链接、年份、英文案例残片、引文符号、来源叙述、半句残句和普通说明句。
27. 误区标题必须是具体错误认知，不能是原文残片、人名案例、泛主题词或“以为X……”套壳标题。
28. 步骤标题必须贴近原文里的真实动作、决策或机制问题，不能只是把误区主题改成“怎么X？”或“如何处理X？”。
29. 步骤标题允许使用不同提问方式或动作式标题，例如 `什么时候该转型，什么时候该坚持？`、`用非引导问题验证假设`、`开发-测量-认知循环怎么搭起来？`，不允许整本书统一套用 `怎么...`。
30. 执行器中只允许保留当前正式生成路径，禁止保留旧版固定主题池、旧版模板生成函数和同名覆盖函数作为可维护入口。
31. **反模板硬门禁（唯一权威版本）**：以下六句为旧版自动生成写死的通用废话，定义在 `scripts/execute_book_module_breakdown.py` 的 `GENERIC_SENTENCES` 常量中，**SKILL.md 与本文件必须逐字一致，禁止在派发 prompt 中改写其中任意一句**。任何模块正文一旦命中即判不合格、禁止晋升、禁止进入结构三：
    - 误区类：`把局部感受当成真实判断` / `用完整计划逃避早期反馈` / `忽略已经出现的反常信号`
    - 步骤类：`先把当前卡点写成可判断的问题` / `再用一个低成本动作拿真实反馈` / `最后根据反馈决定保留、调整或停止`
    - 校验由 `validate_real_content(module_root, title)` 按《书名》精确扫描完成，返回非空列表即打回重写；也可用命令行 `python scripts/execute_book_module_breakdown.py validate --title <书名>` 直接跑。
32. **索引真实性门禁**：模块索引每条必须带真实来源证据；只有经核验的真实模块才允许被结构三（文案结构生成 Skill）装配取用。模板/未校验模块不得作为正式匹配资产。
33. **好书源差异化铁律**：不同书的误区/步骤必须来自各自原书真实论点，严禁跨书套用同一套内层文案；结构三每篇取 2 真实误区 + 6 真实步骤时，必须来自同一本书或明确标注的不同书源。

## 内部能力组合

虽然对外只保留一个总入口，但内部仍要完成三类组合动作：

1. 金句抽取与聚合写入
2. 误区提炼与独立文件写入
3. 步骤提炼与独立文件写入

## 三类模块正式格式

### 金句模块

- 同一级分类下统一进入一个聚合文件。
- 同一级分类下必须先按二级分类分组，例如 `### #风险`、`### #问题`。
- 每条金句必须是可直接用于标题、口播、开头或收口的高传播表达。
- 每条金句正文默认不超过 30 个汉字；长度只计算 `——《书名》` 前面的正文。
- 每条金句必须是完整短句、笃定句，不得是普通描述句、摘要句、解释句。
- 金句正文禁止出现 `本书 / 作者 / 原文 / 书中 / 提到 / 认为` 等来源叙述词。
- 每条金句句尾必须带来源，例如：`——《低风险创业》`。

### 误区模块

- 每个误区文件必须围绕一个具体错误观点展开。
- 正文必须使用 `误区1 / 误区2 / 误区3` 的编号结构，每个文件包含 2-3 个误区。
- 每一条下面至少拓展 3 句，必须说明为什么错、错在哪里、继续这样做会导致什么结果。
- 每一条必须写成面向观众的认知纠偏文案，不得写成书摘解释或依据说明。
- 不能只是把标题换个说法重复一遍。
- 编号标题写完后，正文第一句不能重复编号标题。
- **（实际落地格式）** 每个误区文件顶部只写错误观点标题，正文用 `误区1 / 误区2 / 误区3` 编号展开；文件末尾（品牌页脚前）必须带三行元信息，作为来源与审核依据：
  ```text
  - 一级分类：科学创业
  - 来源文件：《书名》.md
  - 原文依据：该书真实论点 / 章节出处（如「竞争意味着大家都没有利润、产品没有实质差异（第4章 竞争意识）」）
  ```
  `原文依据` 是反模板门禁之外的第二道真实书源证明，缺失即判不合格、不得晋升。

### 步骤模块

- 每个步骤文件标题必须是具体执行问题、决策问题、机制问题，或明确动作标题。
- 标题可以是 `怎么...`、`为什么...`、`什么时候...`、`先...还是先...`，也可以直接用动作式标题；不要求统一句式。
- 禁止重复前缀，如 `怎么怎么...`、`如何怎么...`。
- 正文必须使用 `步骤1 / 步骤2 / 步骤3 / 步骤4` 的连续编号结构，每个文件包含 2-4 个步骤。
- 每一步必须形成执行链，每一步下面至少拓展 3 句，像可直接调用的文案段落。
- 不能只写一句空泛建议。
- 编号标题写完后，正文第一句不能重复步骤标题。
- 禁止写"这一步成立，是因为某书说……"这类依据说明。
- **（实际落地格式）** 每个步骤文件顶部只写具体问题 / 动作标题，正文用 `步骤1 / 步骤2 / 步骤3 / 步骤4` 编号展开；文件末尾（品牌页脚前）必须带三行元信息，作为来源与审核依据：
  ```text
  - 一级分类：科学创业
  - 来源文件：《书名》.md
  - 原文依据：该书真实论点 / 章节出处（如「护城河来自专有技术、网络效应、规模经济、品牌四要素（第5章 后发优势）」）
  ```
  `原文依据` 是反模板门禁之外的第二道真实书源证明，缺失即判不合格、不得晋升。

## 小审审核清单（模块放行前必过）

候选模块晋升正式库前，小审逐项核对，任一不过即退回重写：

1. **反模板门禁**：`validate_real_content` 对该书返回 0 命中（六句通用废话全无）。
2. **正文去作者化**：正文区禁止出现 `本书 / 书中 / 作者 / 原文 / 依据 / 提到 / 认为 / 强调 / 指出` 等来源叙述词，也不得点名作者（如「蒂尔认为」）；来源只保留在 footer 的 `原文依据`。
3. **原文依据必填**：每个误区/步骤文件 footer 必须带 `一级分类 / 来源文件 / 原文依据` 三行，且 `原文依据` 指向该书真实章节论点，不得空泛。
4. **好书源差异化**：误区/步骤内层文案必须来自本书真实论点，严禁跨书套用同一套表达；结构三取用时须同一本书或明确标注不同书源。
5. **表达合规**：误区写明为什么错/错在哪/继续做的后果；步骤形成执行链、每步≥3句可直接调用；不得写成书摘解释或作者观点说明。
6. **索引真实标记**：晋升后 `模块索引.jsonl` 每条带 `source_quality: "real"`，只有 real 才允许结构三装配取用。

## 执行顺序

1. 读取原始资料入库统计，找到目标书目，确认其为正式 `md`。
2. 由 WorkBuddy（LLM）通读原书，按「三类模块正式格式」直接撰写真实模块文件（金句聚合、误区独立文件、步骤独立文件），每个误区/步骤文件必须带 footer 的 `一级分类 / 来源文件 / 原文依据` 三行元信息，且内层正文是该书真实论点、严禁写死/套用通用话术；正文不得出现作者名或 `认为 / 强调 / 指出` 等来源叙述词。
3. 由 LLM 把模块文件直接写入正式库目录（`02_误区模块` / `03_步骤模块`，文件名带《书名》前缀），并写入充分拆解记录；此时索引**暂不**打 `source_quality:"real"`，处于「待审」状态。
4. 运行 `python scripts/execute_book_module_breakdown.py validate --title <书名>` 做反模板门禁：返回非空即打回重写，绝不放行模板内容。
5. 小审对候选做充分性、结构与表达三重审核；不通过则保留为退回记录，不进正式库。
6. 小审通过后运行 `python tools/promote_book_real.py --title <书名>`：内置门禁（命中即拒绝打标）校验通过后，给该书的每条索引打 `source_quality: "real"`，正式放行结构三取用。
7. 晋升后回写 `模块索引.jsonl` 与原始资料入库统计状态。

> `execute_book_module_breakdown.py` 只提供 `validate_real_content(module_root, title)` 反模板门禁；正式误区、步骤正文由专业 Agent 按本合同生成，再经小审审核。

## 执行脚本

- `scripts/execute_book_module_breakdown.py` —— 仅提供 `validate_real_content(module_root, title)`：反模板门禁，按《书名》精确扫描 `02_误区模块` / `03_步骤模块` 是否含六句通用废话，返回不合格文件列表。CLI 用法：`python scripts/execute_book_module_breakdown.py validate --title <书名>`（命中退出码 1）。
- `tools/promote_book_real.py` —— 晋升打标脚本（位于项目根 `tools/`，不在本 Skill 内）：内置调用 `validate_real_content` 门禁，0 命中才给该书每条索引打 `source_quality: "real"`；任一命中即拒绝并退出码 2。CLI 用法：`python tools/promote_book_real.py --title <书名>`。

示例（在 WorkBuddy 加载本 Skill、由 LLM 完成正文创作后调用）：

- 校验：`python scripts/execute_book_module_breakdown.py validate --title 从0到1`
- 晋升：`python tools/promote_book_real.py --title 从0到1`
