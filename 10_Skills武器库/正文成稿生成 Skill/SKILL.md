# 正文成稿生成 Skill

## 定位

这是通用正文生产入口。新任务使用 V19 结构和 V5 正文合同；正文按当前已审核结构候选的完整 FNN 大框架推进，以结构四中人工填写的大框架内容为唯一核心内容输入，不得自行补写任何大框架。

## 输入

- 用户填写完整的文案结构 Markdown：直接 Codex 调用默认使用 `owner-filled-direct`，不要求文件名标记；它只核验当前 V19 审核候选、标题/对标编号、完整 FNN 编号/名称/顺序和完整结构四内容。
- 工作台调用必须使用 `owner-frozen`：文件名以 `√` 或 `✓` 标记、结构四完整且 owner-freeze 回执与当前哈希可核验。冻结是工作台的显式完成标记，不会因填写内容自动产生。
- 对应文案结构中锁定的 `benchmark_case_id`、完整 `big_frameworks`、每个框架的功能定义，以及结构四人工填写的大框架内容。

## 强制边界

- 正文阶段不得检索处理库、输入库、案例卡、开头卡或任何对标案例；结构三资产只供结构设计参考，不能绕过结构四进入正文。
- 核心内容输入是用户填写的结构四。非空格标记 `user-filled` 并原样锁定；整格为空不得建立正文计划。
- 若人工填写内容含已审核案例卡的 `case_copy`，必须保留其第一人称、已发生事实、错误判断和转折；只可补充前后衔接，不能改写成案例说明书、概念总结或新编结果。
- 非核心框架不得出现在结构四，也不得检索资料或复述对标原文；只能按已审核的框架功能、相邻 FNN 推进关系和既有人工填写核心内容生成上下文。
- 每个 FNN 大框架必须声明一个主写作手法、可选辅手法与选择理由。可用手法见正文合同；手法必须与实际展开相符。
- 成稿前逐段通过 `workflow/writing_contract.py` 读取唯一机器源 `contracts/writing-expression-contract-v3.json`，并在计划与候选锁定其 ID、版本、哈希、完整口播原文快照和正文适用规则：普通人无需行业背景即可听懂；口语、短但不断、笃定、结论先行、主动句、段落推进、案例服务观点、去废话、实操者视角、开头冲突与结尾闭环均为强制条件。正文仍不得制造伪对立、不得脱离标题、不得编造事实；必要术语必须用日常话说明。`写作文案表达合同.md` 只供人工阅读，不得作为运行时输入。
- 正文不得读取、携带、引用或校验小框架上下文；不得额外读取对标原文、逐句/句群计划、复刻画像或任何处理库资产。最终 Markdown 仅按大框架成段。

## 执行路径

1. Markdown 输入运行 `scripts/prepare_framework_copy_task.py`，锁定完整 FNN、框架功能定义和结构四核心内容。直接调用默认 `--input-mode owner-filled-direct`；工作台必须传入 `--input-mode owner-frozen`。两种模式都校验标题、对标编号、核心 FNN 编号/名称/顺序及完整性。
2. 小写逐个生成完整 FNN 段落：核心段扩写人工填写内容；非核心段完成自己的框架功能，衔接前后框架。
3. 通过 `scripts/build_framework_copy_candidate.py` 绑定正文和段落方法元数据，生成独立的段落注释文件；运行 `scripts/validate_framework_copy.py`，再用 `scripts/render_framework_copy.py` 生成每段含 `【FNN｜框架｜主：写作手法｜辅：写作手法】` 的逐标点换行预览。
4. 按 V3 机器合同完成自检；再用 `01_Agent系统/02_小审-质量审核Agent/scripts/prepare_framework_final_copy_semantic_review.py` 建立独立语义审稿模板。小审必须逐段按合同规则 ID 引用候选原句和结构四内容；任一项未通过不得发布 `final-copy-v5`。
5. 仅在小审 `approved` 后调用 `scripts/publish_framework_final_copy.py`。它会复核计划、候选、预览、段落注释、正式正文和小审回执的哈希绑定，并从案例对标复刻拆解目录派生正文正式目录：缺失时创建该叶目录，会员后缀完全镜像案例目录，根目录或错类型目录一律拒绝；随后写入 `final-copy-publication-v1` 发布回执并回写正文发布索引。

## 输出合同

完整输入冻结、框架级正文映射和审核字段见 [正文合同](references/copy-contract.md)。
