# 正文成稿生成 Skill

## 定位

这是通用正文生产入口。正文按当前已审核结构候选的完整 FNN 大框架推进：结构四只提供核心框架的冻结内容；开场、转场、观点回扣、行动引导等非核心框架按其已审核的框架功能和相邻推进关系补足。正文不读取对标原文。

## 输入

- 用户确认的文案结构 Markdown；当文件名以 `√` 或 `✓` 标记且结构四完整时，它是工作区所有者的最高权限冻结输入：结构四无需再次送小审。已审核结构候选仍锁定完整 FNN、框架名称与功能定义。
- 对应文案结构中锁定的 `benchmark_case_id`、完整 `big_frameworks`、每个框架的功能定义，以及结构四冻结的核心框架内容。

## 强制边界

- 正文阶段不得检索处理库、输入库、案例卡、开头卡或任何对标案例；结构三资产只供结构设计参考，不能绕过结构四进入正文。
- 核心内容输入是用户冻结的结构四。非空格标记 `user-filled` 并原样锁定；整格为空才标记 `auto-fill-required`，且需写明框架级补全理由。
- 若冻结内容含已审核案例卡的 `case_copy`，必须保留其第一人称、已发生事实、错误判断和转折；只可补充前后衔接，不能改写成案例说明书、概念总结或新编结果。
- 非核心框架不得出现在结构四，也不得检索资料或复述对标原文；只能按已审核的框架功能、相邻 FNN 推进关系和既有冻结核心内容生成上下文。
- 每个 FNN 大框架必须声明一个主写作手法、可选辅手法与选择理由。可用手法见正文合同；手法必须与实际展开相符。
- 成稿前逐段自检：不得制造“非此即彼”的伪对立或与后文冲突；抽象词必须落到可观察场景、动作或判断标准；每段必须服务标题并相对前段新增推进；方案必须写清动作、对象、验证信号与停止条件；开头要给目标读者停留理由，收束只留一个低门槛动作。
- 不接受小框架、逐句/句群计划、复刻画像或任何对标原文作为输入。

## 执行路径

1. Markdown 输入运行 `scripts/prepare_framework_copy_task.py`，锁定完整 FNN、框架功能定义和结构四核心内容。人工冻结结构四只校验标题、对标编号、核心 FNN 编号/名称及完整性，不以旧正式结构文件的路径或哈希阻断调用。
2. 小写逐个生成完整 FNN 段落：核心段扩写冻结内容；非核心段完成自己的框架功能，衔接前后框架。
3. 通过 `scripts/build_framework_copy_candidate.py` 绑定正文和段落方法元数据，生成独立的段落注释文件；运行 `scripts/validate_framework_copy.py`，再用 `scripts/render_framework_copy.py` 生成每段含 `【FNN｜框架｜主：写作手法｜辅：写作手法】` 的逐标点换行预览。
4. 先按[正文语义质量门禁](references/final-copy-semantic-quality-gate.md)完成自检；再用 `01_Agent系统/02_小审-质量审核Agent/scripts/prepare_framework_final_copy_semantic_review.py` 建立独立语义审稿模板。小审必须逐项复核内容兑现、逻辑一致性、具体性、主题聚焦、方案可执行性、开头停留理由、段落推进、口播完整性与行动收束；任一项未通过不得发布 `final-copy-v3`。
5. 仅在小审 `approved` 后调用 `scripts/publish_framework_final_copy.py`。它会复核计划、候选、预览、段落注释、正式正文和小审回执的哈希绑定，再原子写入 `final-copy-publication-v1` 发布回执并回写正文发布索引；补发时只接受与已审核预览完全一致的既有正式正文。
