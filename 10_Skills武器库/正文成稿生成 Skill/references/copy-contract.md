# 通用正文成稿合同 v5

## 输入冻结

正文任务绑定 `structure_input_authority`、用户确认的结构 Markdown 哈希、当前 V19 已审核结构候选哈希、主题、对标案例编号、完整 FNN 总顺序、每个大框架的功能定义，以及唯一 `writing-expression-contract-v3` 的 ID、版本、哈希和正文适用规则 ID。直接 Codex 使用 `owner-filled-direct`：结构四完整即可；工作台使用 `owner-frozen`：还必须验证 `√`、owner-freeze 回执和当前哈希。核心段只锁定结构四中人工填写的大框架名称、顺序和内容；不得从标题或目录猜测案例，也不得读取小框架、对标原文、逐句/句群计划或复刻画像。

## 框架级正文映射

候选使用 `final-copy-v5`，并覆盖 `big_frameworks` 的每一个 FNN 框架。`generation_owner=structure-core` 行以 `filled_content` 锁定同一大框架的结构四内容，并在所属大框架内实质展开；候选、预览和审核均不得出现小框架上下文。`generation_owner=final-copy` 的行没有、也不得伪装成用户填写内容；它依据自身框架功能、相邻推进关系和既有人工填写核心内容补足开场、转场、回扣或收束。每行必须有主写作手法、可选辅手法和选择理由；正文与手法必须匹配。

## 正文边界与发布

- 对标案例只在结构阶段提供编号、框架名称和功能定义；正文阶段不读取案例原文、小框架、处理库、输入库或结构三出处。
- 非核心段不得检索或引用处理库、输入库或结构三出处，也不得引入新的核心结论。
- 正文不得跨 FNN 借用内容、编造新事实或覆盖用户填写内容。
- 正式预览为“标题 → 按完整 FNN 顺序的内联标注与正文 → 唯一品牌尾注”。每段正文前必须单独显示且仅显示一行 `【FNN｜框架｜主：写作手法｜辅：写作手法】`；主/辅手法必须来自当前候选，空辅手法固定显示 `辅：无`。每个中文或英文逗号、句号、问号、感叹号、分号、冒号后换行。
- 同时生成独立段落注释文件，逐段记录框架、功能、内容来源、主/辅写作手法、选择理由与正文段落位置；正式正文已显示 FNN、框架和主/辅写作手法，本文件保留其余审核追溯信息。其 Markdown 也由统一品牌尾注函数规范化。
- 发布仅接受当前 `final-copy-v5` 候选、预览、段落注释和 approved 小审回执；正式路径必须由对标复刻拆解目录派生，目录缺失时创建对应叶目录，禁止根目录或错误类型发布。历史落盘正文只作静态查阅，运行时不再验证、重审或发布。
