# 通用正文成稿合同 v3

## 输入冻结

正文任务绑定用户确认的结构 Markdown 哈希、当前已审核结构候选哈希、主题、对标案例编号、完整 FNN 总顺序及每个大框架的功能定义。不得从标题或目录猜测案例；不得读取小框架、逐句/句群计划、复刻画像或对标原文。

## 框架级正文映射

候选使用 `final-copy-v3`，并覆盖 `big_frameworks` 的每一个 FNN 框架。`generation_owner=structure-core` 的行锁定用户冻结内容并在所属框架内实质展开。`generation_owner=final-copy` 的行没有、也不得伪装成用户冻结内容；它依据自身框架功能、相邻推进关系和既有冻结核心内容补足开场、转场、回扣或收束。每行必须有主写作手法、可选辅手法和选择理由；正文与手法必须匹配。

## 正文边界与发布

- 对标案例只在结构阶段提供编号、框架名称和功能定义；正文阶段不读取案例原文。
- 非核心段不得检索或引用处理库、输入库或结构三出处，也不得引入新的核心结论。
- 正文不得跨 FNN 借用内容、编造新事实或覆盖用户冻结内容。
- 正式预览为“标题 → 按完整 FNN 顺序的内联标注与正文 → 唯一品牌尾注”。每段正文前必须单独显示且仅显示一行 `【FNN｜框架｜主：写作手法｜辅：写作手法】`；主/辅手法必须来自当前候选，空辅手法固定显示 `辅：无`。每个中文或英文逗号、句号、问号、感叹号、分号、冒号后换行。
- 同时生成独立段落注释文件，逐段记录框架、功能、内容来源、主/辅写作手法、选择理由与正文段落位置；正式正文已显示 FNN、框架和主/辅写作手法，本文件保留其余审核追溯信息。其 Markdown 也由统一品牌尾注函数规范化。
- 发布仅接受当前 `final-copy-v3` 候选、预览、段落注释和 approved 小审回执；历史 `final-copy-v1/v2` 可查阅并保持其既有发布绑定。
