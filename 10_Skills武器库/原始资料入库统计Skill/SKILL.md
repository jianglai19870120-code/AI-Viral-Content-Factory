# 原始资料入库统计Skill

## 核心定位

本 Skill 是小息在原始资料层的**唯一正式工具**，承担两件相关但独立的事：

1. **标准化入库**：把任意格式的原始资料，稳定转成正式入库文件（转 md / OCR / 命名清洗 / 单一主分类归位）。
2. **清单与数据中心刷新**：重建来源级清单，并让数据中心只依据 approved、可回溯的正式产物显示拆解状态。

标准化与统计都只作用于 `02_资产中心/01_输入库/` 与内容模块落点，不碰选题、不碰文案、不碰拆解逻辑本身。

## 一、标准化入库（职责①）

把待入库资料变成符合规范的正式原始资料。

- **转 md**：`txt` / `pdf` / `epub` / `docx` 优先转成 `.md`（依赖缺失时优雅降级并提示）。
- **OCR**：扫描型 PDF 在 `--ocr` 下调用 `rapidocr_onnxruntime` 抽取文字（未装则跳过并提示）。
- **命名清洗**：去空白、去非法字符、剥离自动生成前缀（如 `[English (auto-generated)]`、`播客样本-`）；书籍统一《书名》形态。
- **单一主分类归位**：按 `--type` 归到唯一的一级输入目录（`01_推荐好书-源文件` 等），可选 `--subcat` 进入子分类。

入口脚本：`scripts/standardize_input.py`

```
python scripts/standardize_input.py <文件或目录> --type 书籍 [--subcat 科学创业] [--ocr] [--move] --apply
```

标准化产物落入输入库后，按项目硬规则交小审审核，再由对应拆解 Skill 处理。

### 视频文案 Excel 的专用标准化

视频文案源 Excel 保留原文件不改；使用 `scripts/standardize_video_sources.py` 为每条视频生成独立 Markdown 源文档、稳定 `source_id`、来源表行定位、源文件哈希与全文哈希，并写入 `04_视频文案-源文件（会员专享）/00_标准化源文档/`。后续痛点、观点、误区拆解只读取这些标准化源文档，不直接重复解析 Excel。

### 视频文案校对版候选

识别原文存在明显错别字、标点或断句问题时，可使用 `scripts/proofread_video_source.py` 在运行区生成**校对版候选**；原识别源文档永不覆盖。每项改动都必须记录精确原文偏移、原片段、校对片段、类型、理由和状态；语义无法确认的内容只标为待确认，不自动改写。

```
python scripts/proofread_video_source.py --source <逐视频源文档.md> --changes <修改清单.json> --output-dir <.runtime候选目录>
```

完整字段与审核边界见 [视频文案校对版合同](references/视频文案校对版合同.md)。校对候选只可作为后续拆解输入，必须先交小审独立审核，不能直接写入正式输入库或处理库。

### 视频文案五篇批次校对准入

重建视频痛点卡前，使用 `scripts/process_video_correction_batch.py` 按标准化 manifest 的固定顺序每次处理连续 5 篇：全 547 篇预检 → 单篇保守校对（可零改动）→ 小审逐篇审核 → 五篇全通过后才写已审核校对源批次清单。脚本每次只运行一个指定批次，不会自动开启下一批；任何退回都会停批并保留运行区回执。

```
python scripts/process_video_correction_batch.py --batch-number 1
```

详见 [视频文案五篇批次校对准入合同](references/视频文案五篇批次校对准入合同.md)。

当此 Skill 由“视频文案刷新”任务调用时，校对不是独立的前台待办。小姜必须先读取视频痛点覆盖台账，仅接续当前未完成的连续批次：若校对回执缺失，完成本批校对与小审并生成 approved 清单；若清单已齐全，则把同一批交回 `$breakdown-video-pain-cards`。不得跳批、不得自动开启下一批，也不得要求用户在工作台分别点击“校对”或“审核”。

## 二、清单与数据中心回写（职责②）

### 工作台来源级核验（现役规则）

今日工作页的“当前数量/待处理”按**输入来源**统计，不再把处理库卡片数量或输入目录文件数直接当作完成数。运行时由 `workflow/input_inventory.py` 建立独立来源清单并写入工作台 `input_inventory` 表；同一来源产生多张观点、痛点、误区、方案或案例卡时只计一条；小审确认无真实案例闭环的复盘记为已处理、案例卡为 0。

清单按书籍、播客、视频文案、今日复盘、热点事件分别保存。每条记录必须包含 `source_id`、源文件哈希、处理输出数量、状态和状态原因。已拆解必须有可回溯的现役正式输出证据；无法确认来源时不得计入已拆解。今日工作刷新任务只读取状态为“未拆解”的来源。

工作台只读接口为 `/api/today/input-inventory`，按类型过滤使用 `/api/today/input-inventory/{type}`，按来源详情使用 `/api/today/input-inventory/{type}/{source_id}`。清单导出脚本：`scripts/rebuild_input_inventory.py`。

扫描 `02_资产中心/01_输入库/` 下的正式源文件目录，并扫描 `02_资产中心/04_选题库/01_对标账号`，登记资料并判定拆解状态。

### 固定输入（五类一级目录）

| 目录 | 资料类型 |
|---|---|
| `01_推荐好书-源文件` | 书籍 |
| `02_热门播客-源文件` | 播客 |
| `03_热点事件-源文件` | 事件 |
| `04_选题库/01_对标账号` | 对标 |
| `99_今日复盘-源文件（会员专享）` | 复盘 |

> 注：「开头」是 GHK 文案组件，不是原始资料类型，不列入统计。

### 固定输出

- 输入资料清单：`02_资产中心/01_输入库/清单/<资料类型>清单.jsonl` 与同名 Markdown 表格。
- 对标案例清单：`02_资产中心/05_案例库/清单/对标案例清单.jsonl` 与同名 Markdown 表格。
- 数据中心快照、SQLite 索引和事件流水：只由统一回写服务刷新。

### 清单字段

输入资料清单固定为：`source_id`、标题、源文件路径、处理输出数量、状态、状态原因。对标案例清单另包含案例编号、类型、正式三列表路径、审核状态、源稿/拆解哈希及审核回执路径。

### 状态判定规则（按五类内容模块分流）

- **五类维度**：分别扫描 `02_资产中心/02_处理库/01_观点_内容模块`、`02_痛点_内容模块（会员专享）`、`03_误区_内容模块`、`04_解决方案_内容模块`、`05_案例_内容模块（会员专享）`。
- **书籍**：先匹配 `《书名》` 前缀文件，再读取模块正文中的 `来源文件：`、`## 《书名》`、引用署名等来源证据；命中则该维度为 `✓`。
- **播客 / 事件 / 对标**：用源文件标题归一化匹配模块目录/文件名，并检查 Markdown 来源字段与 JSON/JSONL 的 `source_path`、`source_title`、`source_file`；命中则该维度为 `✓`。
- **复盘案例**：读取 `02_资产中心/02_处理库/05_案例_内容模块（会员专享）/02_案例卡索引/案例卡索引.jsonl` 的 `source_path`、`source_title`、`case_id` 与 `card_path` 判断；输入库 `清单/复盘清单` 是唯一人读清单。
- **未命中**：某个维度目录不存在，或目录存在但没有文件名/正文/索引来源证据命中，记为 `○`。

只读取文件系统上的两种可见状态，不调用、不读取任何其他 Skill 的内部状态文件。

## 固定边界

- **负责**：原始资料标准化入库（转 md / OCR / 命名清洗 / 单一主分类归位）+ 入库统计。
- **不负责**：深度拆解、文案生成、选题判断、书源目录长期维护。

## 执行方式

- 标准化：`python scripts/standardize_input.py <源> --type 书籍 [--subcat 科学创业] [--ocr] [--move] --apply`
- 清单重建：`python scripts/rebuild_input_inventory.py [--only <来源类型>]`
- approved 正式发布后的统一回写：`python scripts/refresh_after_approved.py --type <来源类型> --producer <Agent> --reason <原因>`
- 对标案例 approved 发布后的统一回写：`python scripts/refresh_after_approved.py --benchmark-cases --producer xiaojing --reason <原因>`

当前支持：

- 标准化：转 md / 命名清洗 / 单一主分类归位（OCR 可选）
- 回写：从 approved、可回溯的正式产物重建各类来源清单与对标案例清单，并刷新数据中心。
