# 小审审核 Skill

审核对标复刻拆解、通用文案结构、通用正文成稿和视频文案模块。小审独立审核、只写正式回执、不修改候选；未通过不得发布。

今日复盘案例卡只接受 `work-journal-case-card-v12` V12.1：候选和一级源文件都必须有当前 SHA256；小审回执按 `audit-receipt-v3` 绑定二者哈希。每张卡必须有口语化标题、第一人称 `case_copy`，以及 1–3 段可逐字回到一级转写的连续原文；`claim_quote_map` 必须分别标回发生、卡点、决定和结果/当前决定。小审须确认原文足以支撑场景、行动、冲突或误判、判断转折和最终选择；纯观点、方法总结、拼凑故事或编造结果不生成 CASE 卡，审核通过后只记“已处理”。审核结论与真实结果状态只写审核回执和机器索引，不显示在正式案例卡或录音总览。

配图任务使用两道独立门禁：先运行 `01_Agent系统/02_小审-质量审核Agent/scripts/audit_visual_work_package.py` 审核 v4.1 工作包，再运行 `audit_visual_outputs.py` 审核原生最终 PNG。预审必须确认 `model-integrated-chinese`、主脸锚点、合格成图品质参考、本页三层 `source_text_ledger`、2–5 张主卡、每张 1–3 条 `evidence_nodes`、并列分支未被从属条件拆碎以及跨页主视觉组合去重；任何缺证据、正文丰富却证据密度不足、无文字候选、后续程序叠字合同或运行时改 Skill 的工作包直接退回。成图审核必须逐页逐主卡核对：实际可见中文与 `source_text_ledger` 完全一致、标题/主卡/每条证据均已填入、每条证据的对象或关系实际可见、没有空白卡槽和清单外中文、未照抄品质参考的文字/对象、跨页未重复同一“文字 + 对象 + 关系”。审核结论必须绑定最终 PNG 哈希；提示词通过不能替代成图审核。

通用结构审核读取 `文案结构生成 Skill/references/structure-contract.md` 和小审侧 `references/copy-structure-audit-contract.md`；通用正文审核读取 `正文成稿生成 Skill/references/copy-contract.md` 与 `正文成稿生成 Skill/references/final-copy-semantic-quality-gate.md`。新任务只审核 `copy-structure-handoff-v16` / `copy-structure-v16`：先核对共享标题合同、三条母逻辑、扣题结论、逐 FNN 承接与删段断链，再核对完整 FNN 顺序、框架映射、结构三逐条原文证据、冻结结构四和人读预览。案例必须还原事件、误区必须还原原误区、方案必须引用原文步骤；不接受小结构、逐句/句群、蓝图或复刻画像。正文只审核 `final-copy-v3`：候选必须覆盖完整 FNN，核心段兑现冻结内容，非核心段按框架功能完成开场、过渡或收束；审核同时核对段落注释伴随文件、主/辅写作手法及其与正文的匹配、逐标点换行的内联标注预览和事实边界。每段必须有且仅有一行 `【FNN｜框架｜主：写作手法｜辅：写作手法】`，其顺序和字段必须与当前候选一致，缺失、错序或漂移即退回。独立审稿还必须对逻辑一致性、抽象表达落地、主题聚焦、方案执行验证、开头停留理由、段落新增推进、口播完整性和行动收束逐项给出候选内证据；任一项未通过即退回。历史 V1/V2 合同仅可查阅，保留其既有发布状态，不得作为新发布输入。

选题表直连的结构任务还必须携带发布计划：小审独立核验九列目标行唯一、`是否选中=是`、本次锁定的对标编号属于该行以换行或 `<br>` 维护的编号列表且已审核、行指纹未漂移、候选与发布计划哈希一致、正式命名合规且未占用。每个编号是独立分支，回执和发布索引必须锁定本次编号，不能覆盖同一选题的其他编号。未通过不得写正式结构、发布索引或选题状态；状态不得按文件名或目录扫描推断，多编号行只能按可核验发布分支数回写 `已生成一`、`已生成二` 等。

视频文案试跑分两道独立审核：

- 校对版候选执行 `01_Agent系统/02_小审-质量审核Agent/scripts/audit_video_source_correction.py`。必须校验 `source_id`、原识别源路径与文件/全文哈希、校对全文哈希、修改清单偏移和片段，并重放清单验证没有未记录改写。只允许错别字、标点、断句、重复音节；待确认项必须原样隔离。
- 痛点、观点、误区候选执行 `01_Agent系统/02_小审-质量审核Agent/scripts/audit_video_pain_cards.py`。审核旧版 Markdown 卡或 JSON-only `machine-evidence/routed-modules.json`；必须校验分类、唯一 ID、精确原文证据、表达来源声明、待归类隔离和索引路径；若证据来自校对版，每条还必须有可精确回到原识别版的路径、全文哈希、字符定位与片段。JSON 机器候选根含任一 Markdown 浏览卡即退回，未 `approved` 不得渲染正式浏览卡。

两道审核均只接受运行区候选；校对版未 `approved` 不得交给视频文案-痛点卡拆解 Skill，模块卡未 `approved` 不得进入正式处理库或正式索引。痛点表达须原文优先：连续原文直接引用，或仅以字符定位可回溯的片段轻拼接；不得把孤立结论、概括或新增措辞伪装成原话。机器证据以 `pain-expression-completeness-v1` 逐项证明对象/人物、场景、痛点或矛盾、结果或领悟这些原文可得维度被表达承载；短表达只有给出完整性理由时才能通过。

痛点人读字段另设 `pain-card-plain-language-v1` 门禁：`pain_title`、`pain_definition`、`audiences`、`angle_title` 和 `how_to_frame` 必须逐项通过“小学生听得懂、能直接念、说的是具体人和具体事、没有未解释行业词”的复核。标题必须是痛点描述而非分类或概念标签；定义、对象、角度和怎么讲都必须用笃定口语。出现“用户画像、内容策略、价值主张、流量机制、叙事、心智、转化链路、方法论、底层逻辑、商业闭环、颗粒度”等未解释行话，或使用“可能、建议、可考虑、视情况”等回避表述，一律 `returned`。本门禁只审说明字段；原文“表达方式”和“来源”保持原样，不因口语化规则被改写。

547 篇重建使用 `scripts/audit_video_pain_batches.py` 和 `references/video-pain-batch-audit-contract.md`。逐篇校对回执必须连续；批次固定 5 篇、末批 2 篇；上一批未 `approved` 时下一批不得启动。每批还须先把当前及此前 approved 机器证据连续聚合，再复核人读卡暂存、pain ID 去重索引与合并回执，才可由调度器解锁下一批。旧格式清理仅接受已审核的 15 卡/15 索引行计划，必须保留新格式样本。只有完整 547 篇、四账号分布一致且发布暂存、索引和归档清单均通过复核，才允许正式库切换。

视频痛点卡用于文案结构选择时，另执行 `scripts/audit_video_pain_angle_matching.py`，并遵守 `references/video-pain-angle-matching-audit-contract.md`：正式卡的每个角度必须有唯一稳定 `angle_id`、可精确回原文的来源锚点以及与人读卡一一对应的表达哈希；未受影响和仍保留的旧角度不得换 ID 或漂移。结构三选择痛点角度必须绑定该 `angle_id` 与相同来源锚点，并以“对象/场景/核心矛盾/功能适配”四项说明匹配理由；模糊关键词、缺来源或归档/分类法/旧格式混入均退回。
