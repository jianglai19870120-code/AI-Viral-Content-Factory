# 文案结构的人话表达规范

适用于结构一、结构二，以及结构三中已绑定正式资产的全部人读内容：核心金句、论据链、结构推进逻辑、案例描述和方案动作。它只约束人读预览的表达，不改变 `structure_segments`、内容功能合同、命题绑定或资产边界。

## 核心金句

`core_claim` 是用户一眼读懂、也能直接讲出口的核心金句，不是给系统看的摘要。

- 用一句具体判断说清楚“这一点到底要讲什么”；优先写成冲突、反差、因果或结果。
- 让句子脱离表格也成立；避免“本节点讨论”“内容判断应当”“需建立机制”等书面或元话语。
- 优先说人话：能说“很多人以为 A，其实 B 才是关键”，就不要写成“应重新评估 A 与 B 的关系”。
- 不强制同一个句式。案例可先给异常现象，误区可直接点破谣言，解决方案可给明确判断或最少动作。

示例：

- 不写：`本节点应当建立价值判断。`
- 改写：`观众不是不想听干货，而是第一秒没看见这条内容能帮到自己什么。`

## 论据链与方案动作

- 每条论据只推进一个意思，必须能说明前一句为什么成立，不能换词重复核心金句。
- 先给能想象的场景、动作或结果，再补原因；不要只堆“机制、维度、变量、闭环”等抽象名词。
- 方案写清谁在什么情况下做什么，怎样判断有效；案例写清对象、行为、冲突和结果。
- 没有来源时不编造真人、金额、数据或平台规则；可以使用不冒充事实的典型场景。

## 按框架功能表达

不同大框架按自己的内容功能说话：

| 框架类型 | 金句与论据的表达推进 |
| --- | --- |
| 案例 | 熟悉场景 → 反常结果 → 这件事暴露了什么；对比案例必须说清 A、B 与关键差异。 |
| 误区 | 直接点破“大家以为的 A” → 为什么听起来有道理 → 漏洞在哪里 → 真正决定因素 → 继续相信的代价。每个误区攻击不同错误认知。 |
| 痛点 | 具体场景 → 卡在哪里 → 继续这样会付出什么代价。 |
| 观点 | 给出明确判断 → 解释判断成立的条件或原因 → 指向下一步。 |
| 解决方案 | 明确对象与动作 → 给出先后顺序 → 说明什么信号算有效。 |

## 多版本

三条路线仍由五维 `angle_fingerprint` 区分。表达可以同样口语化，但不得把同一个母命题换成不同的口头说法；新路线至少在三个指纹维度上实质不同。

## 正文写作方法的结构适配

以下要求从正文 Skill 的既有写作方法整理而来，只用于结构一至三的核心内容卡片。它们不把结构提前写成正文，也不替代结构三的处理库来源边界。

1. **服从框架功能与标题**：每个核心内容只完成当前 FNN 大框架的任务，并直接服务选题；不得为了凑内容引入脱离当前框架的新结论。
2. **判断有边界、不自相矛盾**：不把必要条件说成唯一条件，不制造“非此即彼”的伪对立；前后节点的判断必须能同时成立。
3. **抽象表达必须落地**：观点、论据和推进逻辑里的关键概念，要落到可观察的场景、行为、选择或判断标准。
4. **每个节点都有新增推进**：相对前一节点，至少新增原因、代价、边界、例子或动作之一；不能只把同一观点换词再说一遍。
5. **方案写成能执行的动作**：写清谁在什么情况下做什么、看什么信号判断有效；只有当前框架本身承担行动收束时，才给出一个低门槛且有完成标准的行动。
6. **按框架选择说法**：开场类框架让目标读者看见对象、冲突或误判代价；观点、痛点、误区、案例、方案仍按各自框架功能表达，不能套同一种句式。
7. **保持完整口播单元**：每格内容读出来必须是完整意思；设问必须带出答案；需要解释的概念用人话说明。

不迁入正文专属要求：逐标点换行、FNN 内联标注、段落注释、发布合同、正文段落长度，以及正文候选的主/辅写作手法字段。
