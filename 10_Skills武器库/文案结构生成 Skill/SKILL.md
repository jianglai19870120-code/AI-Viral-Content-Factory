# 文案结构生成 Skill

## 定位

这是小拆的正式结构生成入口。新链路只消费选题和对标三列表中的 FNN 大框架顺序、名称。

## 输入

- 一个新选题、一个已审核对标复刻拆解编号；或选题表中唯一选中且绑定该编号的行。

## 强制规则

- 新任务只生成 `copy-structure-handoff-v16` / `copy-structure-v16`；V15 及更早版本均为不可改写的历史资产。
- 先共同锁定“选题扣题合同”：目标对象、标题承诺、核心冲突、最终结论、判断完成的标准；三套结构都必须证明这同一承诺。
- 每套结构先写一条不同的母逻辑，再按 FNN 顺序逐节点锁定五项链路：本段回答的问题、承接上一段的前提、本段新增的必要结论、删去本段后会断掉什么、自然引出的下一问。链路未锁定不得检索模块或填写内容。
- FNN 名称、正式类型和框架功能属于 handoff 不可变元数据，候选每行必须继承；结构三仅能以同类型正式模块证明已锁定的节点任务，不能让模块反向改写母逻辑。
- `big_frameworks` 保留完整 FNN 总顺序；结构一至四只显示可映射处理库的核心内容框架，并保持其原始相对顺序。
- 大框架名称可保留序号或说明；只要名称包含且仅包含一个正式内容家族词（观点、痛点、误区、解决方案、案例、推荐理由），即映射为该类型，例如“第二点：误区”映射为“误区”。开场、转场、观点回扣、行动引导等正文专属支撑词优先按支撑段处理。
- 行动引导、开场、转场等非处理库支撑段必须交给 `final_copy_only_frameworks`，只由正文 Skill 在正文收束时生成；不得出现在结构一至四或结构三出处表。
- 结构一至三由小拆围绕选题提出不同内容方向；结构四由用户填写和明确冻结，未冻结不得进入正文。
- 结构一至三的核心内容必须遵守[人话表达规范](references/spoken-structure-writing.md)中的“正文写作方法的结构适配”：内容服从当前 FNN 框架功能与标题，逐节点新增推进，抽象表达落到场景、动作或判断标准；只输出可直接讲出口的核心内容卡片，不提前写成正文段落。
- 不接受或输出小框架、功能蓝图、`structure_segments`、逐句、句群、复刻画像、内容对象池或资产检索结果。
- 结构三的非空核心内容只能从 `02_资产中心/02_处理库` 的同类型正式拆解模块摘取；每条论据必须有 `source_evidence`，逐条写明来源、章节、连续原文摘录、证据角色及其对当前 FNN 任务的支撑。V12 案例卡必须逐字调用其 `case_copy`，并带入连续原文证据和事实边界；不得把案例改成概念说明。案例必须讲清发生的事，误区必须还原原误区和漏洞/后果/纠正，解决方案必须引用带步骤号的原文动作；不得使用 `source_note`、选题表、对标拆解或策划说明作为出处。
- 同类型且语义充分的模块未命中时，该行核心内容与出处必须同时留空，并在 `asset_gap_note` 留下检索缺口；不得跨类型补写。
- 人读稿必须在结构三显示“出处”列；正式发布需要当前 approved 小审回执。

## 执行路径

1. **小姜分配**：完成已审核对标编号与选题表行的预检，锁定单个对标分支。
2. **小拆生成**：运行 `scripts/prepare_structure_task.py --topic <选题> --benchmark-id <编号> --output <handoff>`；再运行 `scripts/build_structure_candidate.py --handoff <handoff> --authoring <小拆策划 JSON> --output <candidate>`。
3. **运行区校验与预览**：运行 `scripts/validate_structure_output.py`，再以 `scripts/render_structure_markdown.py --output <preview>` 生成无内部元数据的人读稿。
4. **小审与发布**：小审审核标题承诺、母逻辑、相邻必然承接、删段断裂、FNN 顺序、框架归属、结构四和预览；approved 后受控发布。
5. **正文桥接**：用户冻结结构四后，正文接受核心框架冻结内容，并按当前候选中正文专属支撑段的标签完成收束。

完整数据合同见 [结构合同](references/structure-contract.md)，结构字段适配见 [人话表达规范](references/spoken-structure-writing.md)。
