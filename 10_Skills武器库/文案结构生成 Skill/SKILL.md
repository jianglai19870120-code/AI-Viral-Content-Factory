# 文案结构生成 Skill

## 定位

这是小拆的正式结构生成入口。新链路同时锁定 FNN 大框架顺序、名称，以及每个大框架内小框架的名称、顺序和原文要点。

## 输入

- 一个新选题、一个已审核对标复刻拆解编号；或选题表中唯一选中且绑定该编号的行。

## 强制规则

- 新任务只生成 `copy-structure-handoff-v19` / `copy-structure-v19`；旧版本的落盘产物仅供人工查阅，系统不再生成、验证、审核或发布。
- 先共同锁定“选题扣题合同”：目标对象、标题承诺、核心冲突、最终结论、判断完成的标准；三套结构都必须证明这同一承诺。
- 每套结构先写一条不同的母逻辑，再按 FNN 顺序逐节点锁定五项链路：本段回答的问题、承接上一段的前提、本段新增的必要结论、删去本段后会断掉什么、自然引出的下一问。链路未锁定不得检索模块或填写内容。
- FNN 名称、正式类型和框架功能属于 handoff 不可变元数据，候选每行必须继承；结构三仅能以同类型正式模块证明已锁定的节点任务，不能让模块反向改写母逻辑。
- `big_frameworks` 是结构一至四唯一的行序列：必须完整保留 F01 至末尾 FNN 的原始顺序，全部大框架均生成和展示。
- 大框架名称可保留序号或说明；只要名称包含且仅包含一个正式内容家族词（观点、痛点、误区、解决方案、案例、推荐理由），即映射为该类型，例如“第二点：误区”映射为“误区”。开场、转场、观点回扣、行动引导等正文专属支撑词优先按支撑段处理。
- 开场、成果背书、提出选题、转场、行动引导等非处理库大框架同样必须出现在结构一至四；结构一、二按其小框架原文要点生成，结构三不检索、不补写，内容与出处留空。
- 结构一至三由小拆围绕选题提出不同内容方向；结构四按完整大框架序列由用户填写和明确冻结，未冻结不得进入正文。
- 结构一至三必须通过 `workflow/writing_contract.py` 读取唯一机器源 `contracts/writing-expression-contract-v3.json`：handoff 与候选锁定其 ID、版本、哈希、完整口播原文快照及结构适用规则；原文中的口语、结论先行、承接推进、观点/案例/信息增量和扣题要求均为强制条件。合同、原文快照、规则索引或哈希缺失，三套角度指纹不实质不同，或出现合同定义的营销钩子/孤立企业套话时一律退回。`写作文案表达合同.md` 只供人阅读，不得作为运行时输入。
- 小框架只作为内部生成与审核的最小覆盖单元：每个大框架必须按其小框架顺序逐项写出内容；V19 人读稿只保留大框架名称与汇总后的大框架内容，不显示小框架名称、顺序、原文摘录或来源证据。
- 结构三仅当大框架具有处理库正式类型且命中语义充分的同类型模块时才可填写；非空内容必须引用处理库同类型正式模块和逐条原文依据。非处理库大框架或未命中模块时，内容、出处和全部小框架卡片必须同时留空，禁止自行补写。
- 同类型且语义充分的模块未命中时，该行核心内容与出处必须同时留空，并在 `asset_gap_note` 留下检索缺口；不得跨类型补写。
- 人读稿必须在结构三显示“出处”列；正式发布需要当前 approved 小审回执。

## 执行路径

1. **小姜分配**：完成已审核对标编号与选题表行的预检，锁定单个对标分支。
2. **小拆生成**：运行 `scripts/prepare_structure_task.py --topic <选题> --benchmark-id <编号> --output <handoff>`；再运行 `scripts/build_structure_candidate.py --handoff <handoff> --authoring <小拆策划 JSON> --output <candidate>`。`authoring` 的每个大框架须提供按锁定顺序排列的 `small_framework_cards`。
3. **运行区校验与预览**：运行 `scripts/validate_structure_output.py`，再以 `scripts/render_structure_markdown.py --output <preview>` 生成无内部元数据的人读稿。
4. **小审与发布**：小审审核标题承诺、母逻辑、相邻必然承接、删段断裂、FNN 顺序、小框架覆盖、框架归属、结构四和预览；approved 后受控发布。发布目录从案例的对标复刻拆解目录派生：缺失时创建对应叶目录，会员后缀必须完全镜像案例目录，禁止发布到文案结构根目录。
5. **正文桥接**：用户冻结完整结构四后，正文按同一完整 FNN 顺序成稿，不自行补写任何大框架。

完整数据合同见 [结构合同](references/structure-contract.md)；运行时写作约束只读 V3 机器合同源，阅读版仅用于人工核对。
